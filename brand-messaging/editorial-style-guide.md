# Editorial Style Guide

## Overview

The **CyberShield Editorial Style Guide** defines grammar, punctuation, and formatting standards for all written content — including documentation, marketing, and internal communication.

It ensures that every message, from product guides to campaign posts, reflects the same level of precision, clarity, and professionalism.

> 💡 **Tip:** Consistency is clarity. Consistency across channels turns content into communication.

***

### Grammar & Mechanics

| **Element**      | **Rule**                                       | **Example**                                                                                         |
| ---------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **Voice**        | Use **active voice** wherever possible.        | <p>✅ “CyberShield detects threats in real time.”<br>❌ “Threats are detected by CyberShield.”</p>    |
| **Tense**        | Present tense for factual, ongoing processes.  | ✅ “The dashboard displays live alerts.”                                                             |
| **Articles**     | Drop unnecessary “the” before product names.   | ✅ “Open CyberShield Control Hub.”                                                                   |
| **Spelling**     | Use **US English** consistently.               | “Behavior,” not “Behaviour.”                                                                        |
| **Numbers**      | Spell out one–nine; use numerals for 10+.      | “Three modules,” “12 updates.”                                                                      |
| **Contractions** | Allowed in marketing; avoid in technical docs. | <p>Marketing: “You’ll love how fast it works.”<br>Docs: “You will need to restart the service.”</p> |

***

### Punctuation Rules

| **Punctuation**         | **Guideline**                                     | **Example**                                             |
| ----------------------- | ------------------------------------------------- | ------------------------------------------------------- |
| **Oxford Comma**        | Always use it for clarity.                        | “Scans, alerts, and reports.”                           |
| **En Dash (–)**         | Use for ranges and relationships.                 | “Pages 5–10,” “AI–powered security.”                    |
| **Em Dash (—)**         | Use for emphasis or interruption.                 | “CyberShield learns — so you don’t have to worry.”      |
| **Quotation Marks**     | Use double quotes (“ ”) for titles and UI labels. | Click “Run Scan.”                                       |
| **Colons & Semicolons** | Prefer short sentences instead of long clauses.   | ✅ “Run the installer. Restart your device.”             |
| **Apostrophes**         | Don’t use for product or brand possessives.       | ✅ “CyberShield features,” not “CyberShield’s features.” |

***

### Formatting Conventions

| **Element**           | **Usage**                                           | **Example**                                         |
| --------------------- | --------------------------------------------------- | --------------------------------------------------- |
| **UI Labels**         | Bold UI text, use Title Case.                       | Click **Run Scan** or select **Dashboard**.         |
| **File Names & Code** | Monospace font.                                     | `config.json`, `api_key`, `POST /scan/start`        |
| **Headings**          | Use emojis + Title Case (for GitBook consistency).  | “🚀 Getting Started”                                |
| **Notes / Warnings**  | Use GitBook callouts with icons.                    | > ⚠️ **Warning:** Restart may take several minutes. |
| **Lists**             | Use numbered lists for steps, bullets for features. | 1️⃣, 2️⃣, 3️⃣ for procedures.                       |
| **Hyperlinks**        | Descriptive labels only (no “click here”).          | ✅ “Learn more about AI detection.”                  |

***

### Capitalization Rules

| **Category**             | **Guideline**                           | **Example**                             |
| ------------------------ | --------------------------------------- | --------------------------------------- |
| **Product Names**        | Always capitalize full name.            | CyberShield Security Suite              |
| **Modules / Components** | Capitalize specific features.           | CyberShield Control Hub, Endpoint Agent |
| **Generic Terms**        | Lowercase unless part of a proper noun. | “the dashboard,” “a scan report”        |
| **Headings**             | Use Title Case; no punctuation.         | “Automated Incident Response”           |
| **Button Labels**        | Title Case, imperative verbs.           | “Start Scan,” “View Report”             |

***

### Terminology & Word Choice

| **Use**                   | **Avoid**           | **Reason**                             |
| ------------------------- | ------------------- | -------------------------------------- |
| “CyberShield platform”    | “Our solution”      | Be specific, not vague.                |
| “AI-powered”              | “Next-gen”          | Avoid buzzwords.                       |
| “Detects” / “Neutralizes” | “Deals with”        | Strong verbs build confidence.         |
| “User” or “Administrator” | “Customer”          | Keep consistent with audience context. |
| “Protection”              | “Security coverage” | Shorter and clearer.                   |

***

### Style Consistency Across Channels

| **Content Type**       | **Tone**                | **Formatting**               | **Goal**           |
| ---------------------- | ----------------------- | ---------------------------- | ------------------ |
| **User Documentation** | Clear, calm, neutral    | Step-by-step, callouts       | Guidance           |
| **SDK / API Docs**     | Technical, concise      | Code blocks, JSON formatting | Developer accuracy |
| **Marketing Copy**     | Confident, persuasive   | Short paragraphs, icons      | Engagement         |
| **Emails**             | Friendly, supportive    | CTA buttons, brief text      | Conversion         |
| **Social Media**       | Conversational, concise | Emojis, short lines          | Connection         |

***

### Best Practice Guidelines

✅ Always check for consistency across tone, punctuation, and structure.\
✅ Avoid using unnecessary capitals in mid-sentence product references.\
✅ Keep content inclusive — avoid gendered language and jargon.\
✅ Test formatting readability on both light and dark modes.\
✅ Revisit the style guide quarterly as product voice evolves.

🧠 **Info:** Editorial discipline is invisible when done right — it makes every word feel intentional.
